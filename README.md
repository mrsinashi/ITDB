# ITDB

Учёт компьютеров IT-отдела — веб-приложение вместо большой Excel-таблицы.
Центр системы — компьютер: где стоит (адрес → отделение → этаж → кабинет), номер места,
пользователь, сеть, железо, отметки. Есть история изменений, вход с ролями и выгрузка
в Excel.

## Из чего состоит

| Часть | Что |
|---|---|
| Сервер | Debian, Python 3.13 (подходит 3.11+), PostgreSQL 17 |
| Backend | FastAPI + SQLAlchemy, миграции Alembic — папка `backend/`. Сессия базы на запрос — `session=Depends(get_db)` (`db.py`); непредвиденная ошибка → ответ 500 «Ошибка на сервере: …», полный текст — в журнале uvicorn. Встроенные столбцы ПК (таблица, карточка, выгрузка, История) описаны в одном месте — `api_columns.py` |
| Frontend | Vue 3 без сборки — папка `frontend/static/` (сервер отдаёт её сам): разметка `index.html`, стили `app.css`, код — модули в `js/` (карта — в начале `js/main.js`) |
| Миграции | `alembic/versions/` |

Правила оформления — в `DESIGN.md` рядом с проектом (в git не входит).

Все команды ниже выполняются **из корня проекта** (там, где лежит этот файл).

## Первая установка

1. Создать базу и пользователя PostgreSQL (пароль — свой). На сервере всё тестовое
   помечено `dev`: у копии для проверок база и пользователь `itdb_dev`, простое имя
   `itdb` — только у боевой копии (раздел «Боевая копия»):
   ```
   su postgres -c "createuser -P itdb_dev"
   su postgres -c "createdb -O itdb_dev itdb_dev"
   ```
2. Файл `.env` в корне проекта (в git не попадает; программа, миграции и тесты читают
   его сами). Значение с `&` — в кавычках:
   ```
   DATABASE_URL="postgresql+psycopg://itdb_dev:ПАРОЛЬ@localhost/itdb_dev"
   ```
   В копии для проверок (dev) можно добавить `ITDB_LABEL=DEV` — рядом с «ITDB» в меню
   и во вкладке браузера появится пометка, чтобы не спутать с боевой копией.
3. Виртуальное окружение и библиотеки:
   ```
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   ```
4. Создать таблицы в базе и первого администратора:
   ```
   .venv/bin/alembic upgrade head
   .venv/bin/python backend/create_admin.py
   ```

## Запуск (dev — для проверки патчей)

```
.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8001 --app-dir backend
```

Открыть в браузере `https://itdb.lan:8443` или `https://192.168.0.181:8443` — https
даёт Caddy (раздел «Боевая копия», `deploy/Caddyfile`). Остановить — Ctrl+C.
Настройки программа берёт из `.env` сама. Постоянная работа для коллег — раздел
«Боевая копия».

**Только https.** Программа отвечает отказом на любой запрос не по https (и на
страницу входа тоже), кроме запросов с самого сервера — например,
`curl http://127.0.0.1:8001/login.html` или SSH-туннель. Поэтому `--host 0.0.0.0`
больше не нужен: снаружи вход только через Caddy.

Документация API — `https://СЕРВЕР:8443/docs`.

## Роли

- `admin` — всё, включая импорт;
- `editor` — просмотр и правка;
- `reader` — только просмотр.

Ещё одного администратора можно создать той же командой
`.venv/bin/python backend/create_admin.py`.

Остальных пользователей заводит администратор в интерфейсе — страница
«Пользователи» (значок справа в верхнем меню, виден только ему): новый пользователь, логин, ФИО, должность, роль,
новый пароль, отключение (удаления нет). Свою роль и отключение себя изменить нельзя —
так в системе всегда остаётся администратор. Свой пароль, логин, ФИО и должность любой
пользователь меняет в меню со своим именем справа вверху (кнопка ✎).

Логин — латинские буквы (большие и маленькие), цифры, точка, дефис, подчёркивание;
хранится как ввели, а входить можно в любом регистре (`Ivanov`, `ivanov`, `IVANOV` —
один и тот же логин, второго такого завести нельзя).

## Сканер: подключения к GLPI, GSIT, Jabber

Верхнее меню: слева — Таблица, Дерево, Vacuum, Сканер (последние два — редактору и
администратору); справа значками — Справочники, История, Пользователи, Настройки.

Страница «Сканер». Вкладка «Подключения» (только
администратор): адреса и учётные записи источников (в шапке блока — число ПК или
пользователей по последнему сбору; итог проверки — в подсказке у «подключено»), значок с
вилкой — проверить подключение, «Собрать» (когда собирали — в подсказке у кнопки); под
формой — только ошибки. Подсети — таблица: «+» справа от неё (или значок на панели) —
строка добавления последней строкой таблицы, поля — под своими столбцами; в поле подсети —
список подсетей /24, где есть ПК из базы, а в списке их нет. «Изменить» (✎ или двойной
клик) — та же строка на месте подсети. Так же устроены «Пользователи».

Пароли и токены хранятся в базе **зашифрованными** ключом `ITDB_SECRET_KEY` из `.env`
(копия базы без `.env` их не раскрывает). Боевой копии ключ добавляет
`deploy/update.sh` сам. В dev — один раз, из корня проекта, затем перезапустить программу:
```
echo "ITDB_SECRET_KEY=$(.venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')" >> .env
```
Ключ не терять и не менять: без него сохранённые пароли не прочитать — их придётся ввести
заново. У dev и боевой копии ключи разные — это нормально.

GLPI и GSIT: ITDB работает через их REST API (`apirest.php`) — один и тот же у GSIT
(GLPI 9.5) и GLPI 11. Лучше отдельный пользователь только для чтения. В GLPI:
«Настройки → Общие → API»:
- «Включить REST API» (в GLPI 11 — «Включить **устаревший** REST API»: предупреждение
  про новый API можно принять — новый API есть только в GLPI 11, а GSIT его не знает);
- «Разрешить вход по учётным данным» (или выдать пользователю токен API);
- клиент API: по умолчанию есть только «full access from localhost» (адрес 127.0.0.1) —
  добавить свой клиент (например, «ITDB») с диапазоном IP от адреса сервера ITDB до
  него же. Токен приложения (App-Token) — по желанию: если он задан у клиента, его
  нужно вписать и в ITDB.

Профилю пользователя GLPI для сбора нужно чтение: «Компьютеры», «Программы»
(для VNC), «Антивирусы» идут вместе с компьютером. Чего нельзя прочитать, того в
данных просто не будет (об антивирусах сбор предупредит в итоге).

### Сбор из GLPI и GSIT

Кнопка «Собрать» — в блоке источника (он должен быть «Включён» и сохранён) и на
вкладке «Проверка» (там — из всех включённых источников разом, и из Jabber). Сбор идёт
в фоне (на 600 ПК — около минуты), страницу можно закрыть. **В таблицу ПК ничего не пишется**: записи лежат отдельно, показывать и
принимать отличия — блочки в Таблице и вкладка «Проверка» (ниже).

- Берутся только **свежие** записи: проверенные агентом (GLPI — «Дата последней
  инвентаризации», GSIT — «FusionInventory — последняя связь») не раньше, чем «не
  старше N дн.» в настройках источника. Без такого поля сбор не начинается.
- Мусорные серийные («Default string», «To be filled by O.E.M.», «1,90E+14»…),
  заводские UUID-заглушки, виртуальные адаптеры (VirtualBox, Hyper-V, VPN, случайные
  MAC Wi-Fi), IPv6 и 169.254.x не учитываются. Серийный или MAC, одинаковый у трёх
  записей и больше, — тоже (плата на 17 ПК с одним номером).
- Дубли — записи источника с тем же железом (агент поставили заново): остаётся самая
  свежая.
- С каким ПК ITDB связана каждая запись (вкладка «Проверка»). По признаку — номер записи
  (столбец «GLPI» — для GLPI, столбец «GSIT» — для GSIT), MAC, настоящий серийный; «привязать?» — совпало
  только имя; «конфликт» — признаки указывают на разные ПК или у ПК другой MAC /
  серийный: такой записи значения не предлагаются, пока не решишь вручную («да, это
  он», «нет, не он», «привязать к ПК…», «забыть решения» — администратор).
  Сопоставление считается по текущим данным таблицы: поправил MAC — обнови вкладку,
  пересобирать не нужно. Решения — в Истории.
- Время «Проверен» — как его отдаёт GLPI (время его сервера).
- **Названия.** Значения сравниваются с таблицей по смыслу: «Win 10» = «Windows 10»,
  «Pentium J3710» = «Intel Pentium J3710», «Lenovo ThinkCentre M600» = «M600» (слова
  вроде Intel, Microsoft, Pro, 22H2 не в счёт; диски 250 и 256 ГБ — один диск). Главное —
  как записано в таблице: значение источника показывается так, как оно уже названо у
  сопоставленных ПК или в Справочнике. Если не догадалось — двойной клик по отметке в
  подробностях записи: «=» одно и то же (для всех ПК), «≠» разное, «⇐» в таблице своё;
  список — вкладка «Названия», там же удалить.
- **«В таблице своё» (⇐)** — когда в таблице намеренно другое: например, модель «ЕГИСЗ»
  у партии ПК с платой «ASUS PRIME H370-PLUS». Пара «ASUS PRIME H370-PLUS — ЕГИСЗ» — не
  расхождение, но и не «одно и то же»: ПК с такой платой без «ЕГИСЗ» в таблице получит
  предложение «ASUS PRIME H370-PLUS», а не «ЕГИСЗ».

### Значения сканера и «Проверка»

У ПК, сопоставленных по признаку или вручную, из включённых источников сканер
предлагает значения (в названиях таблицы). Ситуации: **отличается**, **в таблице
пусто**, **неточно** (источники предлагают разное или значений несколько — например,
два VNC-сервера; программы с «Viewer» в названии сервером не считаются), **в таблице
часть** (один IP из двух — не расхождение). Сами в таблицу данные не пишутся.

- **Таблица.** Кнопка со счётчиком (до «99») показывает значения сканера блочками под
  значениями ячеек (наведение на включённую кнопку — что значат цвета). Клик по блочку —
  карточка рядом: «Взять из сканера», «Оставить как есть» (этому ПК; с галочкой — всем ПК
  с такой парой значений, как «ЕГИСЗ» при плате ASUS), «Своё» — своё значение
  записывается как правильное: у названий (модель, ОС, ЦП…) значение источника дальше
  называется так у всех ПК (соответствие «=» на вкладке «Названия»), у остального (IP,
  MAC, VACUUM…) этому ПК это значение сканера больше не предлагается;
  карточку можно двигать за шапку, Esc или клик мимо — закрыть. В карточке ПК (тоже
  только при включённой кнопке) у поля — блочок и значки ✓ ✕. Цвета блочков,
  «Показывать» и «Без кнопки» (показывать всегда) — Справочники, блок «Значения сканера».
- **VNC.** Если установлено несколько VNC и среди них TightVNC — сервер TightVNC
  (UltraVNC рядом с ним ставят ради просмотрщика); несколько других — «неточно».
  Применяется при следующем «Собрать».
- **HOSTNAME** в таблице — каким имя должно быть, поэтому другое имя из GLPI / GSIT сканер
  только показывает («имя на ПК другое» — переименуй компьютер); взять его в таблицу нельзя
  (можно, только если в таблице имя пустое).
- **Диски и MAC.** Агенты GLPI и FusionInventory пишут объём диска в «двоичных» МБ
  (128 ГБ = 122 070 МБ) — объём считается как на наклейке (128, 240, 256, 480, 512…),
  сначала — по названию модели диска. MAC — все адаптеры железа (Ethernet, Wi-Fi,
  Bluetooth), без VPN и виртуальных; в таблице MAC больше, чем видит источник, — не
  расхождение, а если источник видит ещё и новый — предлагается дописать его.
- **Материнская плата.** GLPI часто отдаёт название платы как модель ПК. «Это материнская
  плата» в карточке у блочка модели (или значок платы в «Проверке») — название пишется
  этому ПК в столбец «Мат. плата» и закрепляется: у всех ПК оно предлагается в этот
  столбец, а не в «Модель» (вкладка «Названия», отметка «→»; удалить — там же).
- **Номера записей.** У сопоставленного ПК сканер предлагает номер его записи в столбцы
  «GLPI» и «GSIT»; номер в ячейке — ссылка на запись (в карточке ПК — значок рядом).
  Столбец «Агент» (раньше назывался «GSIT») — стоит ли на ПК агент.
- **Jabber** предлагает VACUUM. ПК ищется только по IP: кто в Jabber с адреса ПК (сейчас
  или не раньше срока «Актуальны» у подключения Jabber, по умолчанию 7 дней) — дописать.
  Адрес у нескольких ПК или больше 3 человек с одного адреса — не предлагается; человек
  записан у другого ПК — «неточно». Из ячейки сканер никого не убирает: кто не подключался
  дольше срока — жирным оранжевым (в подсказке — сколько дней), кого в Jabber нет (удалён,
  опечатка) — жирным красным. Логин с латинской буквой вместо русской («c» вместо «с»)
  предлагается заменить на настоящий, а не дописать второй.
- **Повторы** (HOSTNAME, IP, VACUUM, MAC, ИНВ, серийный, GLPI, GSIT) — красным блочком
  выделяется само повторяющееся значение, а не вся ячейка.
- **Оформление значений** (Справочники): цвет текста, фон, жирный, курсив, подчёркнутый,
  зачёркнутый; фон — заливкой всей ячейки или блочком у самого значения (кнопка рядом с
  фоном). Ctrl + клик по кнопке цвета сбрасывает этот цвет.
- **Выделения в Таблице** (Справочники, внизу): как показывать повтор, «имя на ПК другое»
  (по сканеру), логин VACUUM, которого нет в Jabber или который давно не подключался, и
  прошедший срок «Временно до». Фон — блочком у значения.
- **Диски:** флешки и внешние диски (USB — по названию или по интерфейсу из GLPI / GSIT)
  сканер в DRIVE не предлагает.
- **Копирование:** Alt + клик копирует значение под курсором — в Таблице и во всех
  остальных таблицах (Дерево, История, Vacuum, Сканер, Пользователи, Справочники).
- **Взять разом.** В Таблице: выделить строки → «Выбрано» → «Взять из сканера…» — выбрать
  тип предложения и столбец. Воронка справа от включённой кнопки «Значения сканера» —
  только строки с предложениями.
- **Антивирусы.** Фильтр столбца — по состоянию (работает, базы устарели, выключен) и по
  названию; сортировка — сначала по состоянию.
- **«Сканер» → «Проверка»** (вкладки: Подключения, Проверка, Названия;
  редактору видна «Проверка»). Строка — ПК в таблице с его записями GLPI и GSIT, или запись,
  которую не удалось уверенно связать с ПК. Фильтры: «Нужно решить» (по умолчанию),
  «Не узнал ПК», «Предлагает другое», «В порядке», «Нет в таблице», «Отклонённые», «Все».
  Клик по строке — подробности: поле | в таблице | GLPI | GSIT | Vacuum (кто в Jabber с
  адреса ПК) | предлагается (отметка
  «= ≈ ≠» — между значением таблицы и источника; когда источник проверял ПК — в подсказке
  у его названия); у каждого
  предложения ✓ (взять) и ✕ (оставить как есть), у отклонённых — «вернуть»; «ещё у N ПК» —
  показать и выделить ПК с такой же парой. Значение «в таблице» правится двойным кликом;
  двойной клик по отметке «= ≈ ≠» — решение по названиям («=» одно и то же, «⇐» в таблице
  своё), в том числе для многострочных значений. Справа — антивирусы, полные названия,
  решения. «Названия»: как это работает — кнопка «?» на панели. Плашка у строки: взять / оставить всё, «да, это он», «привязать к ПК…», «это не
  он», «забыть решения». Выделение — как в Таблице (Ctrl / Shift + клик, Ctrl +
  протягивание, Ctrl+A, Esc),
  «Выбрано: N ▾» — взять или оставить всё предложенное у выбранных, «да, это они».

- **Столбец «Антивирусы»** (Таблица, карточка ПК, выгрузка): антивирусы из записи GLPI
  (нет там — из GSIT), сопоставленной с ПК, каждый строкой; цвет — по состоянию
  (работает / базы устарели / выключен). Что показывать, каким цветом и как называть — Справочники, блок
  «Антивирусы»: глаз у состояния — показывать или нет, глаз у названия — не показывать
  этот антивирус (например, Windows Defender); двойной клик по названию или ✎ — своё,
  короткое название (пусто — как в источнике). Состояние — блочком с фоном, как значения
  справочника. В таблице столбец не правится.

### Jabber (VACUUM) и страница «Vacuum»

«Собрать» у Jabber (или на «Проверке», или кнопка обновления на странице «Vacuum») берёт
из веб-админки ejabberd: список всех пользователей с «Последним подключением» (страница
`users/1-1000/`; потом спрашивается на 100 больше — пока пользователей прибавляется), кто
в сети и с какого IP (страница пользователя), группы общего ростера и их участников. Пока
идёт сбор, на странице «Vacuum» — полоса «просмотрено из».

Страница «Vacuum» (вкладка верхнего меню): Пользователь | Группы | HOSTNAME | Последний IP
| Подключение. HOSTNAME — ПК таблицы с этим IP (клик — карточка ПК); в таблице такого нет —
как его называет GLPI / GSIT (курсивом). Красным — пользователя уже нет, а в группе он
остался (убрать из группы); оранжевым — не входит ни в одну группу; для них — свои
фильтры. Смотреть — редактор и администратор, собирать — администратор.

## Как применить патч этапа

Изменения приходят файлом `_patches/stageNN_….patch` (папка `_patches/` в git не
попадает).

1. Положить файл в `_patches/`.
2. Проверить, что патч ложится без ошибок (ничего не меняет):
   ```
   git apply --check _patches/stageNN_….patch
   ```
3. Применить:
   ```
   git apply _patches/stageNN_….patch
   ```
4. Если в описании этапа сказано «нужна миграция»:
   ```
   .venv/bin/alembic upgrade head
   ```
5. Перезапустить сервер (Ctrl+C и снова команда из раздела «Запуск»).
6. Проверить в браузере и закоммитить.

## Обновление из GitHub

```
git pull
.venv/bin/pip install -r requirements.txt
.venv/bin/alembic upgrade head
```

Затем перезапустить сервер. Если библиотеки и миграции не менялись, лишние команды
ничего не делают — выполнять их можно всегда. Боевая копия обновляется одной командой —
см. ниже.

## Боевая копия (постоянная работа)

Рядом с dev-копией (`/opt/itdb-dev`, запуск вручную на `127.0.0.1:8001`, снаружи —
`https://…:8443`) работает боевая — `/opt/itdb`: своя база, служба systemd (запуск с
сервером, перезапуск при падении), снаружи — Caddy с https на обычных портах 443 и 80
(с 80 — перенаправление на https, заголовок HSTS). Сама программа слушает только внутри
сервера, `127.0.0.1:8000`, и не по https не отвечает. Файлы для неё — в
папке `deploy/`. Порядок работы: патч → dev → проверка → коммит в GitHub →
`deploy/update.sh` на боевой.

Адреса: `https://itdb.lan` и `https://192.168.0.181` (другие — поправить
`deploy/Caddyfile` и сертификат).

### Установка (один раз, под root)

1. Caddy, база и пользователь PostgreSQL `itdb` (пароль — свой, не как у dev):
   ```
   apt install caddy
   su postgres -c "createuser -P itdb"
   su postgres -c "createdb -O itdb itdb"
   ```
2. Код и библиотеки:
   ```
   git clone https://github.com/mrsinashi/ITDB.git /opt/itdb
   cd /opt/itdb
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   ```
3. Файл `/opt/itdb/.env` (пароль пользователя `itdb`; пометки `ITDB_LABEL` здесь нет):
   ```
   DATABASE_URL="postgresql+psycopg://itdb:ПАРОЛЬ@localhost/itdb"
   ```
   ```
   chmod 600 /opt/itdb/.env
   ```
4. Данные: перенести из dev-базы (вместе с пользователями системы и историей) —
   скрипт возьмёт адреса баз из `.env` обеих копий и откажется, если в боевой уже
   есть компьютеры:
   ```
   /opt/itdb/deploy/copy-db.sh /opt/itdb-dev
   ```
   Или начать с пустой базы: `.venv/bin/alembic upgrade head` и
   `.venv/bin/python backend/create_admin.py`.
5. Служба:
   ```
   cp /opt/itdb/deploy/itdb.service /etc/systemd/system/
   systemctl daemon-reload
   systemctl enable --now itdb
   systemctl status itdb
   ```
6. Сертификат от внутреннего CA — на имя и на IP сразу. Ключ и запрос создаются на
   этом сервере:
   ```
   mkdir -p /etc/caddy/certs && cd /etc/caddy/certs
   openssl req -new -newkey rsa:2048 -nodes -keyout itdb.key -out itdb.csr \
       -subj "/CN=itdb.lan" -addext "subjectAltName=DNS:itdb.lan,IP:192.168.0.181"
   ```
   `itdb.csr` подписать на сервере сертификации (в сертификате должно остаться
   `subjectAltName` — имя и IP; если у CA есть промежуточный сертификат — дописать его
   в конец файла сертификата). Готовый сертификат положить как
   `/etc/caddy/certs/itdb.crt`, затем:
   ```
   chown root:caddy itdb.key itdb.crt && chmod 640 itdb.key
   ```
   Корневой сертификат CA должен быть в доверенных на ПК коллег (если ваш CA уже
   раздаётся по сети — ничего делать не нужно).
7. Caddy:
   ```
   cp /opt/itdb/deploy/Caddyfile /etc/caddy/Caddyfile
   caddy validate --config /etc/caddy/Caddyfile
   systemctl reload caddy
   ```
8. Проверить: `https://192.168.0.181` в браузере (замок без предупреждений), вход,
   таблица. `http://192.168.0.181` должен перенаправлять на https. Dev-копия —
   `https://192.168.0.181:8443` (когда она запущена).

Caddyfile при обновлении не копируется сам: если в коммите он менялся — повторить
шаг 7.

### Обновление боевой копии

После коммита этапа в GitHub:
```
/opt/itdb/deploy/update.sh
```
Скрипт: `git pull` → библиотеки → миграции → перезапуск службы; на первой ошибке
остановится, и служба продолжит работать на прежнем коде.

### Если что-то не так

- Журнал программы: `journalctl -u itdb -e`; Caddy: `journalctl -u caddy -e`.
- Сертификат: `openssl x509 -in /etc/caddy/certs/itdb.crt -noout -subject -ext subjectAltName`.
- Сменить имя или IP: строка сайта в `/etc/caddy/Caddyfile` и новый сертификат с тем
  же набором `subjectAltName`, затем `systemctl reload caddy`.

## Миграции

- Посмотреть, на какой версии база: `.venv/bin/alembic current`.
- Последняя версия в коде: `.venv/bin/alembic heads`.
- Откатить одну миграцию: `.venv/bin/alembic downgrade -1`.

Схему базы руками не править: новые поля для компьютеров добавляются в интерфейсе
(«пользовательские поля»), остальное — только миграциями.

## Тесты

Проверяют API: вход и роли, пользователей, таблицу и карточку, правку и историю, архив, выгрузку,
пользовательские поля. Работают с **отдельной** базой: при каждом запуске все таблицы
в ней удаляются и создаются заново. В имени базы должно быть `test` — иначе тесты не
запустятся.

Один раз:
1. Создать тестовую базу (владелец — пользователь dev-копии):
   ```
   su postgres -c "createdb -O itdb_dev itdb_test"
   ```
2. Добавить в `.env` отдельной строкой (пароль — как в `DATABASE_URL`):
   ```
   TEST_DATABASE_URL=postgresql+psycopg://itdb_dev:ПАРОЛЬ@localhost/itdb_test
   ```
3. Поставить библиотеки для тестов (`pytest`, `httpx2`; серверу они не нужны):
   ```
   .venv/bin/pip install -r requirements-dev.txt
   ```

Запуск (из корня проекта; адреса баз тесты берут из `.env` сами):
```
.venv/bin/pytest
```

В конце — `N passed`. Если что-то упало, pytest покажет тест и строку, где значение
не совпало. Тесты не трогают рабочую базу и не мешают запущенному серверу.

## Импорт из Excel

Разовая загрузка старой таблицы (лист `list`) — только в пустую базу, под
администратором, через `/docs`: сначала `POST /api/import/analyze` (что будет загружено
и какие найдены ошибки в данных), затем `POST /api/import/apply` с `confirm=true`.
